# MOA エディタ 仕様書 v2.0（editor.py）

マスターデータ（Character / Outfit / Background / Action）を編集する、ビルダーとは別のアプリ。
データモデル・コンパイル・検証の規則は **SPEC.md v2.0** に従う。この文書はエディタ固有の動作と、
エディタ導入に伴うビルダー側の小さな変更（12章）を定める。

## 変更履歴

- v2.0（2026-10-31）SPEC v2.0（Background / Action 分割）に合わせて全面改訂。
  Situation を廃止し、Background / Action の編集、mossItems のカード式編集（8章）、
  使用中 Action の上書き保存（9章）、新規作成時の初期値（10章）、外部変更の検知（1章）、
  ビルダー側の変更（12章）、受け入れテスト（13章）を追加。Scene の gen は従来どおり（家の標準値はワークフロー JSON 側に置く）
- v1（2026-10-31）初版（Situation 時代の決定事項）

## 0. 起動と構成

- `editor.py`（同じフォルダ、同じ venv）。`python editor.py [--data <フォルダ>] [--port] [--host]`
- 既定ポートは **7863**（7860 はビルダー、7861 / 7862 は Forge Neo が使用中）。`config.yaml` の `editor.port` でも変更できる（起動オプションが優先）
- `moa/core` をビルダーと共通で使う。エディタ固有のコードは `moa/editor/` に置く（画面は `moa/editor/ui/`、Gradio に依存しない処理は `moa/editor/logic/`）
- ビルダーとエディタは同時に起動してよい。同じ `--data` を指すこと

## 1. 基本制約（ユーザー決定）

- 編集対象は **Character / Outfit / Background / Action** の4種。Scene はビルダーだけが扱う
- **ID は変更できない**（フォームでは読み取り専用で表示）
- **削除機能は作らない**（エンティティ、フォルダ、`_folder.yaml` のいずれも）
- できるのは「ID 以外の項目の編集」と「新規追加」だけ
- **新規追加**：ID は作成時にだけ入力する。形式（`^[a-z0-9_]+$`）と重複（同じルート内の索引全体）をその場で検証して表示する。
  Outfit の id に `none` は使えない。ファイル名は `<id>.yaml`。保存先フォルダはツリーで選ぶ
- **複製して新規作成**：既存の内容を初期値にした作成フォームを開く。新 ID 欄の初期値は `<元のid>_copy`（編集可）。保存先の初期値は複製元のフォルダ
- **保存時の検証**：スキーマ検証＋SPEC 9.2 の意味チェック（下表）。**エラーがあれば保存しない。警告だけなら保存できる**
- **書き戻し**：ruamel.yaml（YAML 1.2）で読み込んだ CommentedMap の、変更した項目だけを差し替える。無関係なコメント・キー順・書式を壊さない。
  複数行の文字列は `|` ブロック（LiteralScalarString）で書く。値を空にした任意項目はキーごと消す（空文字を残さない）。ただし必須項目（moss、anima、mossCaption など）は空文字でもキーを残す
- **原子的な書き込み**：一時ファイル（`<name>.yaml.tmp`）に書いてから置き換える
- **外部変更の検知**：項目を読み込んだときのファイル更新時刻を覚えておき、保存直前に比べる。
  変わっていたら（VS Code やビルダー、エクスプローラーなど外部で変更された）保存を止め、
  「ファイルが外部で変更されています」と表示して **［再読み込み（編集を破棄）］［上書き保存］** の2択を出す

保存時の検証（エンティティ別。SPEC 9.2 と同じ規則をエディタの保存前にも適用する）：

| 対象 | エラー | 警告 |
|---|---|---|
| 共通 | スキーマ違反、新規 ID の形式違反・重複 | — |
| Character | `defaultOutfit` の参照先がない | — |
| Outfit | id が `none` | — |
| Background | プレイスホルダーがある、bbox の大小逆転 | bbox のはみ出し（自分の canvas に対して）、anima の人数タグ・solo |
| Action | 書式不正なプレイスホルダー、未宣言スロットの使用、`outfits` の未宣言キー・参照先なし、bbox の大小逆転、スロット保護違反（1b章） | 未使用スロット、推奨背景の参照先なし、bbox のはみ出し（推奨背景の canvas、無ければ 1536×1024 に対して）、anima の人数タグ・solo、スロット追加で影響を受ける Scene（1b章） |

- エラー・警告は、フォーム直下に **項目のパス付き**で一覧表示する（例：`mossItems[2].bbox`、`outfits.left`）

## 1b. スロットの保護（Action。ユーザー決定）

- 既存の Scene から参照されている Action（どれかの Scene の `action` がこの id）では、
  スロットの**削除と名前変更を禁止**し、**追加だけを許す**。違反は保存時のエラーで、参照している Scene の一覧を表示する
- 参照されていない Action では、スロットの削除・改名も自由（新規作成時の `main` を改名する場合など）
- スロットを追加すると、参照している既存 Scene は「未割り当てスロット」でコンパイルエラーになる。追加は許すが、保存時に影響を受ける Scene の一覧を**警告**で表示する
- スロットの改名・削除をしたときは、同じ Action 内の `outfits` のキーとプレイスホルダーは**自動では書き換えない**（未宣言スロットのエラーとして表示し、ユーザーが直す）

## 1c. Background のコピーオンライト保存（ユーザー決定）

- Scene から参照されている Background（どれかの Scene の `background` がこの id）を保存しようとすると、**元のファイルは上書きせず、新しい id の複製として保存する**
- 「使用中」の判定は Scene の `background` だけで行う（Action の推奨背景 `background` は含めない）
- 保存ボタンを押すと確認欄を出す：「この背景は N 件の Scene で使われているため、複製として保存します」＋参照 Scene の一覧（表示名と id）＋**新 ID 欄（初期値 `<元のid>_copy`）**＋［複製として保存］［キャンセル］
- 新 ID には新規作成と同じ検証をかける。保存先は元と同じフォルダ。保存後は、編集画面を新しい複製に切り替える（元は未編集の状態に戻る）
- 既存 Scene は元の Background を指したまま。複製を使うかどうかは、ビルダーで Scene の背景を選び直して決める
- 参照されていない Background は、通常どおりその場で上書き保存する

## 2. フォルダ

- **新規フォルダ作成：許可する。** ツリー下の［＋フォルダ作成］から、ツリーで選んでいるフォルダの中に作る。作成先は4ルート（`characters/` `outfits/` `backgrounds/` `actions/`）の配下だけ。新しいルートは作れない
- フォルダ名の検証（エディタとビルダーで同じ関数を使う。`moa/core` に置く）：
  - 空、`.`、`..` は不可。パス区切り（`/` `\`）は不可
  - 先頭が `_` または `.` は不可（`_folder.yaml` やスキャン対象外フォルダとの衝突を避ける）
  - Windows で使えない文字 `< > : " | ? *` と制御文字は不可。末尾の空白・ピリオドは不可
  - 予約名 `CON` `PRN` `AUX` `NUL` `COM1`〜`COM9` `LPT1`〜`LPT9` は不可（大文字小文字を区別せず、最初のドットより前で判定。`con.txt` も不可）
  - 日本語の名前は使える。同じ場所に同名のフォルダがあれば不可
- フォルダ作成時に `_folder.yaml` は作らない
- **`_folder.yaml` の編集：許可する。** ツリーでフォルダを選ぶとフォームがフォルダ用（`name` / `description` / `order`）に切り替わる。
  `_folder.yaml` がないフォルダでは保存時に新しく作る。全項目を空にしても削除はしない（空のマップのファイルとして残す）
  - `order` は複数行テキスト（1行に1つ、ファイル名またはフォルダ名）。存在しない名前は警告
- **ファイル移動・フォルダの改名・削除は扱わない。** 参照は id で行うため、エクスプローラー等で移動・改名しても参照は壊れない。
  その場合はエディタとビルダーの［再読み込み］で反映される（README にも書く）

## 3. 画面構成（Gradio、3カラム）

```
+--------------------------------------------------------------------------------+
| MOA エディタ                 保存状態：● 未保存の変更あり / 保存済み   [再読み込み] |
+---------------+---------------------------------+------------------------------+
| ツリー (3)    | 編集フォーム (5)                | プレビュー (4)               |
|               |                                 |                              |
| ルート切替    | ID（読み取り専用 / 新規時は入力 | プレビュー対象の選択（5章）  |
| [キャラ|服装| |   ＋検証表示）                  | [プレビュー更新]             |
|  背景|行為]   | 種別ごとの項目（4章）           | 「未保存の内容でプレビュー中」|
| パンくず      |                                 | 補完したキャストの表示       |
| 一覧（📁/📄） | [保存] [複製して新規作成]       | MOSS JSON（読み取り専用）    |
|               | 確認欄（1c・9章、外部変更）     | Anima（読み取り専用）        |
| [＋新規作成]  | エラー・警告一覧                | ネガティブ MOSS / Anima      |
| [＋フォルダ作成] | YAML表示（折りたたみ・閲覧のみ）| bbox プレビュー図（8章）     |
+---------------+---------------------------------+------------------------------+
```

- ツリーはビルダーと同じ方式（パンくず＋一覧で1階層ずつ降りる。`_folder.yaml` の表示名、SPEC 8章の並び順）。プルダウンにしない
- 一覧の項目は `表示名（ファイル名）`。使用中の Background / Action には、参照している Scene の件数を併記する（例：`海辺（beach.yaml）・Scene 3件`）
- **未保存の変更がある状態で別の項目を選ぶ／ルートを切り替える／再読み込みする**と、確認行（［破棄して移動］［キャンセル］）を出して止まる。勝手に移動しない
- **raw YAML の直接編集は作らない**（コメント保持の書き戻しを守るため）。閲覧用の読み取り専用 YAML 表示は可
- ［＋新規作成］は、今のルートの種別の空フォーム（10章の初期値）を、今いるフォルダを保存先として開く

## 4. 種別ごとのフォーム

共通の入力方式：

- **一覧項目（`tags`、`metaTags`、`slots`）**：1行のテキスト欄にカンマ区切りで入力する。保存時に各要素の前後空白を除き、空の要素は捨てる。`slots` は重複不可
- **複数行の文章・タグ**（moss、anima、mossCaption、ネガティブ、bodyHair など）：複数行テキスト欄
- **服装指定の三値コントロール**（Character の `defaultOutfit`、Action の `outfits.<slot>`）：
  ラジオ「未指定（キーを書かない）／none／Outfit を選ぶ」＋Outfit の検索選択欄（名前で絞り込み）。`null` は書かない
- **参照の選択**（推奨背景など）：名前で絞り込める検索テキスト＋一覧。プルダウンにしない

| 種別 | 項目 |
|---|---|
| Character | id、name、group、tags、**sex**（female / male のラジオ）、defaultOutfit（三値）、moss、anima、bodyHairMoss、bodyHairAnima、negativeMoss、negativeAnima |
| Outfit | id、name、tags、moss、anima、negativeMoss、negativeAnima |
| Background | id、name、tags、rating（safe / sensitive / explicit）、**canvas**（w、h の整数。16の倍数でなければ警告）、metaTags、mossCaption、**mossItems（8章のカード）**、anima、negativeMoss、negativeAnima |
| Action | id、name、tags、rating、**background**（推奨背景。未設定可）、slots、**outfits**（スロットごとに三値コントロールを並べる。slots の内容に追従）、**extras**（female / male / others の整数、0以上。全部0なら `extras` キーを書かない）、metaTags、mossCaption、**mossItems（8章のカード）**、anima、negativeMoss、negativeAnima |

- Action のフォームには、プレイスホルダーの書き方の小さなヘルプを常時表示する（`{{slot}}`、`{{slot.outfit}}`、`{{slot.bodyHair}}` と、宣言済みのスロット名の一覧）
- Background のフォームには「プレイスホルダーは使えない」「キャストの姿や行為は書かない」の注意を表示する

## 5. プレビュー

- 編集中（**未保存**）の内容を使ってコンパイル結果を見る。保存ファイルには一切触らない。画面に「未保存の内容でプレビュー中」と表示する
- 実装：`moa/core` に、**索引の一部をドラフトで差し替えたリポジトリの見え方**（オーバーレイ）を用意し、`compile_scene` をそのまま使う。
  ドラフトは新規（未保存の新 id）でもよい
- 合成 Scene（保存しない仮の Scene）を作ってコンパイルする。選ぶもの：

| 編集中の種別 | 選ぶもの | 初期値 |
|---|---|---|
| Character | Action、スロット、Background | Action は「このキャラを使っている Scene」があればその Action とスロット、無ければ一覧の先頭。Background は Action の推奨背景 |
| Outfit | Action、スロット、Character、Background | Character はそのスロットの補完キャスト。**ドラフトの服装は Scene 層（`cast.<slot>.outfit`）に差し込む**（いちばん優先される位置）。あわせて「通常の解決順ならどこで効くか（Action 指定・キャラ既定に負けるか）」を表示する |
| Background | Action | 「この背景を使っている Scene」の Action があればそれ、無ければ一覧の先頭 |
| Action | Background | 推奨背景、無ければ一覧の先頭 |

- **キャストの補完**：ドラフトを差し込まないスロットは、①その Action を使っている既存 Scene があれば、その Scene のキャスト（服装指定も）、
  ②無ければキャラ一覧の先頭から順に埋める。補完したスロットと使ったキャラを「補完：left = skyla_bw（Scene beach_chat__trio から）」のように表示する
- 選択はすべて名前で絞り込める検索＋一覧。［ツリーで選択中のものを使う］ボタンも置く
- 表示：MOSS JSON、Anima、ネガティブ（MOSS / Anima。適用 ON/OFF に関係なく合成済みのものを表示）、人数タグと実効 rating、エラー・警告、bbox プレビュー図（8章）
- 更新は［プレビュー更新］を押したときだけ（キー入力ごとにコンパイルしない）。エラーがある場合は結果の代わりにエラーを表示する

## 6. 保存の流れ

1. 検証（1章の表）。エラーがあれば止める
2. 外部変更の検知（1章）。変わっていれば止めて2択
3. 種別ごとの確認：
   - Background が使用中 → 1c章の複製保存の確認欄
   - Action が使用中 → 9章の参照 Scene 一覧の確認欄（［保存］［キャンセル］）
   - スロット追加の警告（1b章）がある → 確認欄に影響を受ける Scene を併記
4. 書き込み（ruamel、原子的）。索引を更新し、ツリーの表示も更新する
5. 「保存しました：<フルパス>」を表示する

## 7. 新規追加の流れ

- ［＋新規作成］または［複製して新規作成］→ 新 ID 欄が入力可能なフォーム。入力中に形式・重複を表示
- 保存先フォルダはツリーで今いるフォルダ（複製は複製元のフォルダ）。フォーム上に保存先のパスを表示する
- 保存すると、通常の編集画面（ID は読み取り専用）に切り替わる

## 8. mossItems の編集 UI（カード式）

- Background と Action のフォームで同じ部品を使う
- **1カード** ＝ 番号（#1, #2 …）＋ label ＋ caption ＋ bbox の4数値（y_min, x_min, y_max, x_max）＋［↑］［↓］［削除］＋［全面］
  - label：`object` / `text` を候補にした、自由入力もできるドロップダウン
  - caption：複数行テキスト欄（Action ではプレイスホルダー可、Background では不可）
  - bbox：整数入力4つ。［全面］はキャンバス全体（`[-H/2, -W/2, H/2, W/2]`）を入れる
- ［アイテム追加］でカードを末尾に追加する（label=object、caption 空、bbox は全面）
- **実装方式**：最大 **8 枚**のカードを最初から用意し、表示／非表示を切り替える（ビルダーのキャスト枠と同じ方式。部品を動的に生成しない）。
  8枚あるときは［アイテム追加］を無効にし、「最大8件」と表示する
- **bbox プレビュー図**（表示専用）：キャンバスの枠と中心線の上に、各カードの bbox を四角と番号で描いた画像（PIL で生成）。
  Background のアイテムと Action のアイテムで色を分ける（プレビュー5章で両方を重ねるとき）
  - キャンバス：Background 編集中は自分の canvas。Action 編集中は推奨背景の canvas、無ければ 1536×1024（プレビューで Background を選んでいればその canvas）
  - はみ出した四角は警告色で描き、警告一覧にも出す（エラーにしない。SPEC 9.3）。大小逆転はエラー
  - 再描画は、カードの追加・削除・並べ替え、［全面］、［プレビュー更新］のときだけ（キー入力ごとに描かない）
- 四角をマウスで動かす編集は作らない（将来）

## 9. 使用中 Action の保存

- Action は Background と違い、**使用中でもその場で上書き**する（キャラ・服装と同じ「1か所直せば全部直る」方針。コピーオンライトは Background だけの例外）
- 根拠：過去の生成結果は各 Scene の `compiled`（seed・プロンプト・画像）に残るので、上書きしても履歴は壊れない。変わるのは既存 Scene の次回のコンパイル結果だけ
- 安全策（情報表示のみ）：使用中の Action を保存するときは、参照している Scene の一覧を確認欄に出す（1c章と同じ見せ方。複製は作らない）
- スロットの保護（1b章）はそのまま適用する

## 10. 新規作成時の初期値

| 種別 | 初期値 |
|---|---|
| Background | canvas 1536×1024、rating safe、mossCaption・anima は空、mossItems は0件 |
| Action | slots `main` の1つ（未参照のうちは改名自由）、rating safe、mossItems はカード1枚（label=object、caption 空、bbox 全面 `[-512, -768, 512, 768]`）、extras なし（全0） |
| Character | sex female、moss・anima は空、defaultOutfit は**未指定**（none ではない）、bodyHair は書かない |
| Outfit | moss・anima は空 |

- 必須項目が空のまま保存すると、moss / anima / mossCaption は空文字として保存できる（Background の mossCaption・anima は空でよい。SPEC 4.3）。name が空ならエラー
- 複製作成と Background の複製保存では、新 ID 欄の初期値を `<元のid>_copy` にする

## 11. やらないこと（将来）

- 削除、ID の変更、ファイル移動、フォルダの改名・削除、raw YAML 編集、複数エンティティの一括操作
- bbox のマウス編集
- Scene の編集（ビルダーの仕事）

## 12. ビルダー側の変更（エディタ導入に伴うもの）

1. **マスターデータ変更の表示**：ビルダーで Scene を開いたとき、保存済みの `compiled.mossPrompt` / `animaPrompt` と、今コンパイルした結果が違えば、
   「保存時から内容が変わっています（キャラ・服装・背景・行為の編集など）」と表示する。違いの中身（MOSS / Anima のどちらか）も示す。
   `compiled` にプロンプトが無い Scene では表示しない
2. **新しい Scene の生成パラメータ**：変更しない（SPEC 13.5 のとおり、Scene.gen には**動かした項目だけ**を書く）。
   家の標準値（MOSS 50/3.0、Anima 14/1.8/0.45）は**ワークフロー JSON 側の値として設定する**ので、新規 Scene に gen を事前に書き込む処理は作らない（ユーザー決定）
3. **Scene の保存先フォルダの作成**：新規 Scene の保存先を選ぶところに［＋フォルダ作成］を置き、`scenes/` 配下に新しいフォルダを作れるようにする（2章と同じ名前の検証）
4. **外部変更の検知**：ビルダーの Scene 保存にも1章と同じ検知（更新時刻の比較と2択）を入れる
5. **ポート**：`config.yaml` の `builder.port`（既定 7860）でも変更できるようにする（起動オプションが優先）
